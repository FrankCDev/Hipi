# 产品原则

本文件落实[愿景](../../VISION.md)中的六个核心标签。各项是设计要求，具体实现与首版范围仍需评审。

## 1. 围绕完整工作闭环

核心路径是：目标 → 上下文与授权 → 执行与协作 → 成果与验收。

- 任务要有可理解的目标、工作区、输入和预期成果。必要时澄清范围，避免让用户先理解内部技术结构。
- 用户应能了解 Agent 将访问什么、修改什么、向哪里发送数据，以及自己授予了哪些权限。
- 长任务允许用户查看过程、补充信息、调整方向与取消。前台与后台工作的关系必须明确。
- 成果需要清晰的入口、必要的来源与验证证据。区分已完成、部分完成、失败、被取消与等待验收；“Agent 停止输出”不等于用户目标完成。

## 2. 状态真实、默认简单

- 明确区分排队、执行、等待用户、等待外部服务、断线、恢复、失败、取消与完成等用户可理解的状态；具体状态模型在实现前定义。
- 进度只能来自可信证据。没有可计算进度时，展示当前活动与等待原因，不编造百分比或预计完成时间。
- 默认展示目标、当前状态、关键动作和结果；日志、工具细节与诊断按需展开。
- 操作结果必须可感知。解释错误的影响和可执行的下一步，保留用户输入，避免失败后丢失上下文。
- 危险操作、授权请求、取消和退出的语义一致；不能把关闭窗口暗示为任务必然停止。

## 3. 完整设计系统与友好交互

- 建立一致的排版、间距、颜色、图标、层级、动效、焦点和组件状态规范，形成产品自身的视觉质量。
- 设计覆盖首次使用、空状态、加载、无权限、离线、错误、部分成功、恢复和完成；同时覆盖长任务、长文本、大量日志及多任务切换。
- 支持键盘操作、可见焦点、合理的点击区域、屏幕阅读器语义与减少动态效果的偏好。
- 信息密度适合专业工作。保持关键操作可发现，复杂信息逐步展开；避免用动效妨碍阅读或用刷新打断输入与滚动。
- 组件库可作为基础，但默认组件组合不能代替完整设计与真实场景验证。

## 4. 主题是正式产品能力

- 使用语义化主题变量表达背景、表面、文字、边框、强调与状态色，避免散落硬编码。
- 支持全局字体，以及经定义的区域级字体、配色、背景覆盖；区域边界、继承优先级与重置行为必须一致、可解释。
- 提供可用预设、即时预览、导入、导出和重置。配置应有格式版本、校验与错误提示，错误主题不能使产品无法使用。
- 对缺失字体提供回退；验证中文与其他文字、代码字体、缩放、对比度和焦点可见性。
- 主题是受校验的数据配置，不允许任意可执行主题脚本。背景资源也需明确来源、加载与安全策略。

## 5. 国际化从第一天纳入设计

- 用户可见文案集中管理，使用稳定的英文层级 key，例如 `task.status.waiting`；不以展示文案充当标识。
- 日期、时间、时区、数字、单位和复数遵循语言环境，不通过拼接片段构造句子。
- 验证中文输入法组合输入、快捷键冲突、长文案、多行布局、字体回退与缩放。
- 布局为文本长度变化预留空间；目标语言及是否需要从右到左布局，须在语言支持范围评审时明确。

## 6. 三个平台都是一等平台

Windows、macOS、Linux 的核心工作能力和质量标准一致。快捷键、窗口、菜单、文件选择、路径、通知、系统主题和辅助功能尊重平台习惯。平台差异必须明确说明并验证，不能只以某个平台可运行代表跨平台完成。

最低系统版本、架构与硬件要求待评估；不能先写未经验证的兼容承诺。

## 7. 插件生态是核心要求

- 定义清晰的扩展契约、版本与兼容策略、生命周期和故障反馈，让扩展可开发、可安装、可控制、可诊断。
- 区分 MCP、Skills、运行时扩展与 UI 插件：分别说明工具或资源连接、任务方法与上下文、执行能力、界面贡献的职责；不能把不同机制混为同一种权限模型。
- 用户能理解插件来源、能力与权限，能启用、禁用、卸载和撤销授权；权限扩张必须显式处理。
- 插件异常应被控制在明确边界内。隔离机制的实际保护范围必须说明，不能把单独进程宣传为权限沙箱。
- **首版建议，待评审**：交付真实扩展契约、官方示例和安装、启停、兼容性检查、权限与隔离的最小闭环；插件市场、排名与商业化分发可后置。生态不是仅有一个插件入口或演示页面。

## 8. 信任来自可验证的行为

- 持久状态、断线重连、取消、退出和恢复必须有清晰体验。外部操作结果未知时，展示不确定性，不能自动宣称成功或安全重试。
- 凭据、敏感上下文和日志按最小必要原则处理；诊断分享前说明内容与目的，并进行脱敏。
- 更新、数据迁移与故障恢复需要可解释的进展和失败路径，不能以升级为由静默丢弃工作。
- “可靠”“稳定”“流畅”由真实场景验收，具体方法见[工程原则](ENGINEERING-PRINCIPLES.md)。

## 9. 消息与文件工作台

- 消息支持流式 Markdown 绘制，覆盖未闭合结构与连续更新，并保持选择、滚动、键盘和输入体验。
- 右侧提供类 IDE 的项目文件列表、文件查看、代码编辑及最新修改 Diff；比较基线必须明确，不能把最近变动等同于 Agent 全部成果。
- 支持 Word、Excel、PDF、图片与 CSV 展示；具体格式覆盖与保真范围需验证，Office 展示不等于完整 Office 编辑。
- Agent 或外部程序修改正在编辑的文件时，保留未保存输入并处理版本冲突，不静默覆盖。预览不可信文件不能绕过权限或自动上传外部服务。
- 工作台的资源契约、安全、候选库和验收要求见[工作台设计](WORKBENCH.md)。
