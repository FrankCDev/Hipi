# Hipi Work 文档入口

这里记录全新跨平台 Agent Work 客户端 Hipi Work 的目标和原则。产品工程标识为 `hipi-work`，仓库名保持 Hipi；`client` 仅用于内部客户端接口模块。当前文档是设计与开发的共同基线，不是功能交付清单或生产就绪声明。

## 阅读顺序

1. [愿景](../../VISION.md)：产品目标、六个核心标签与尚未决定的问题。
2. [产品原则](PRODUCT-PRINCIPLES.md)：工作闭环、交互、设计系统、主题、国际化、插件与信任体验。
3. [工程原则](ENGINEERING-PRINCIPLES.md)：运行时边界、持久化、安全、测试、性能与交付标准。
4. [架构决策](ARCHITECTURE.md)：Electron 技术方向、UI 与核心边界、IPC/HTTP 契约及待验证的工程方案。
5. [工作台设计](WORKBENCH.md)：流式消息、文件列表、代码编辑、Diff 与多格式预览。
6. [开发规范](DEVELOPMENT-STANDARDS.md)：代码、组件、异步、测试、评审、依赖与发布的执行标准，以及尚待实施的自动门禁。
7. [1.0 RC 首版执行范围](RELEASE-SCOPE.md)：用户已授权推进的本地单用户、多工作区、多任务闭环、后置内容与交付检查点；不是实现完成声明。
8. [页面清单](SCREENS.md)：页面职责、关键状态与下一步主工作台高保真交互验证。
9. [验收清单](ACCEPTANCE.md)：按风险列出可观察场景、证据要求与实际结果记录方式；当前产品验收尚未运行。
10. [工程蓝图](DESIGN-BLUEPRINT.md)：核心领域详细架构入口，涵盖会话、运行时恢复、资源与扩展；领域评审先于生产实现。
11. [仓库开发规则](../../AGENTS.md)：执行开发任务时必须遵守的具体规则。
12. [第二阶段实施范围](PHASE-TWO.md)：可信连接、持久目录、草稿恢复与工作台体验的历史阶段边界；后续范围由 RC 基线接替，实际验收单独记录。
13. [桌面宿主纵向实现](DESKTOP-HOST.md)：Electron 窗口、受限 bridge、独立 runtime 与退出恢复；开发中，桌面运行证据单独验收。
14. [真实模型配置边界](MODEL-CONFIGURATION.md)：公共 PI 模型接口、凭据所有权与付费恢复风险；当前第一实施纵向，具体状态与证据由该文档记录。
15. [历史分页与文本边界](HISTORY-BOUNDS.md)：协议 2 的历史分页、原文块与传输限制；源码和定向测试已实现，GUI 验收仍待运行。
16. [1.0 RC 跟踪](RC-TRACKER.md)：最新授权、功能矩阵、实施依赖、证据规则及 RC 阻断；优先用于判断下一步和真实完成状态。
17. [文件工作台依赖审查](DEPENDENCY-REVIEW.md)：编辑器、文档解析与 PDF 的精确版本、来源、许可证、安装审查和剩余发布要求。
18. [桌面诊断导出](DESKTOP-DIAGNOSTICS.md)：原生预览与本地导出、严格字段白名单、资源边界及尚未完成的原生验收。

20. [工具包生命周期](TOOL-PACK-LIFECYCLE.md)：声明式工具包安装、固定版本绑定、模型披露、撤权与历史授权；格式见[编写指南](TOOL-PACK-AUTHORING.md)。

23. [离线维护操作](STORE-MAINTENANCE.md)：Node CLI 的备份、核验、隔离恢复、历史读取与导出；平台资格及功能限制明确列出。

## 文档约定

- “必须”“不得”表达产品或工程约束；“建议”“待评审”“待评估”表达尚未批准的方案或范围。
- 已确定方向与候选方案分开记录。未决定的框架、版本、性能预算和首版范围，不得在实现或汇报中当作既定结论。
- 原则变更需说明用户影响、取舍与验证方法，并同步相关文档。具体技术决策在评审通过后记录依据、替代方案和后果，无需提前制造空模板。
- 文档描述目标；实现状态、验证结果和已知限制必须另有真实证据，不得从目标反推功能已完成。
- 2026-10-19 用户已授权负责人作普通工程决定并持续推进 1.0 RC。旧设计的“待评审”不再构成等待用户的默认前置条件；工程决定仍需记录，安全确认、实际测试和跨平台证据要求不变。范围冲突以首版执行范围和 RC 跟踪为准。
