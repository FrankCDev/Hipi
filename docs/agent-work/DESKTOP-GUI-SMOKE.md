# Packaged desktop GUI smoke

This deterministic acceptance probe starts the packaged application's real main entrypoint, sandboxed renderer, preload, and utility process. It supplements the [packaging gates](DESKTOP-RELEASE.md); it does not approve a release or close all [RC gates](RC-TRACKER.md).

## Run and prerequisites

After building and packaging the current source on the target OS/architecture, run from the checkout with Node 24.19.0:

```sh
node apps/hipi-work-desktop/scripts/smoke-packaged-gui.mjs
```

The runner accepts no directory overrides. It locates the host-native unpacked package and requires release provenance matching the complete current build input set and hashes, including UI sources and smoke scripts. The shared build snapshot is checked before launch and again before success. The main/provider/profile isolation checks remain explicit: an older package containing an unused helper is rejected before launch. Rebuild after changing these inputs.

Linux requires an existing `Xvfb` executable, a non-root account, and working Chromium sandbox support. The runner allocates its own display with `-displayfd` and disables X11 TCP listening. It does not install packages, change system permissions, use `--no-sandbox`, or disable web security. Missing display/sandbox capability is a failure, not a skipped success. macOS and Windows require a usable native GUI session; packaging on a headless runner alone does not satisfy that condition. Their real launch failures must be reported as failures and resolved on a suitable runner or test machine.

No installed application or user directory is required. The runner checks free disk space before copying the complete unpacked application into a fresh canonical temporary directory with spaces and Chinese characters. A separate private `mkdtemp` directory owns the profile. Only explicitly allowed environment variables are inherited; home/configuration directories are isolated and provider credentials are not passed through.

## Main-process isolation boundary

`--smoke-data-root=<path>` is accepted only with `--provider=deterministic`. The main process validates a canonical, dedicated direct child of the OS temporary directory, rejects symlinks/junctions and unexpected root contents, and verifies private ownership on POSIX. It creates and verifies the profile/session/log/crash directories, calls `app.setPath`, and checks `app.getPath` before requesting the single-instance lock. Production launches without this flag retain their normal paths. Invalid arguments show the localized startup error and exit nonzero before lock, session, or runtime initialization.

`--user-data-dir` is also passed as an early native-stage hint. The isolation guarantee is the explicit main-process path boundary and runtime checks, not an assumption that this Chromium switch alone configures Electron's entire profile. The application never deletes the supplied directory. Only the runner that called `mkdtemp` may clean up its own roots.

## Observed behavior and evidence

The real executable starts normally, without `ELECTRON_RUN_AS_NODE` or a substituted application entrypoint. A temporary port-zero CDP listener is used only for this process lifetime. Discovery and WebSocket endpoints must use literal `127.0.0.1` and the observed port; the only accepted renderer URL is `hipi-work://app/index.html`. Renderer Node access must remain unavailable and the actual preload bridge must exist.

The runner uses Chromium input events and visible DOM controls to select English labels, create a Chinese-named workspace and conversation, choose the deterministic model, and send Chinese text. It observes incremental assistant DOM updates and the confirmed execution result. It then requests normal application quit, verifies successful native process exit and listener closure, and reopens the same profile. The same two persisted message identities and contents must return without duplication. No application RPC is invoked directly to create or complete this scenario.

The catalog, store owner, workspace owner, workspace database, and `DevToolsActivePort` must exist in the runner-owned canonical paths. Renderer exceptions, console errors, error-level log entries, crashes, ambiguous targets, timeouts, unclean exits, and remaining packaged helpers all fail the run.

Before completed and reopened screenshots, `gui-fonts.mjs` checks the exact visible Chinese workspace and user-message fixture nodes and records their actual rendered font families, custom-font flags, and glyph counts through [CDP CSS.getPlatformFontsForNode](https://chromedevtools.github.io/devtools-protocol/tot/CSS/#method-getPlatformFontsForNode). Linux must report positive bundled Noto Sans SC glyph use for both nodes; macOS and Windows retain system-font priority and record the fonts actually used. Waiting for font loading alone is not accepted as rendering evidence. These node statistics accompany screenshots and do not establish complete Unicode coverage or replace visual review. `gui-fonts.test.mjs` tests the protocol calls and platform requirements; the actual rendering result requires native CI.

On both launches, the runner opens Tool activity through its visible control and requires a successfully loaded task-record or retained-result section and an explicit empty page for this no-tool fixture. It also refreshes the page and checks again. An application-level read error fails even when the browser console is quiet. Details and activity dialogs are closed before the final conversation screenshots.

Settings language selection is exercised inside the real settings popover. Model status and file-permission overlays must display their controls and restore trigger focus on Escape. The conversation actions menu is navigated with keyboard events to open Rename and cancel without changing the title. The sidebar View details preview must likewise close and return focus. These focused interaction checks do not constitute a complete keyboard or accessibility audit.

Conversation details and file permissions must have viewport-contained right-placement dialog frames and a visible, enabled Close control with a successful center hit test. When actual body content overflows, native wheel input must reach its bottom while Close remains reachable. Both are closed through actual mouse input; permissions are reopened separately to preserve the Escape/focus check. A non-overflowing fixture is recorded as such, not claimed as long-content acceptance.

Before opening the next overlay, the harness waits for both removal and actual trigger-focus restoration across rendering frames. Radix schedules close autofocus after unmount; DOM disappearance alone is not completion. This avoids racing the previous overlay's deferred focus restoration. It does not certify rapid physical-user interaction: real GUI results are still required, and a popup that loses focus during ordinary use remains a product defect rather than grounds for forced clicks or retries.

The nested Appearance dialog must close on Escape while retaining its parent Settings popover and returning focus to its trigger. The theme button must produce an observed `html[data-theme="dark"]` state and an unobstructed dark screenshot. The original Light, Dark, or Follow system preference is read from the actual labeled Theme control and restored through that form and Save, not by writing application storage. Simply toggling twice would lose an original system preference. Fresh deterministic completion and the inspected model/permission overlays must have no unexpected `role="alert"`, including application errors that never reach the browser console.

After the ordinary completion screenshot, Tool packs is exercised through Settings and real input: paste a bounded deterministic JSON fixture, validate its exact source digest without installation, install initially disabled, enable, read the full immutable source, inspect workspace/conversation/model disclosure, explicitly consent, authorize, revoke, disable and uninstall. Scope IDs come from the visible conversation receipt, not application RPC. After cold restart, only read controls are used to verify the same scope, uninstalled package, revoked binding, retained exact source and empty active-binding view. The flow checks the actual authorization submit button rather than the preceding expiry combobox. This validates management only: no message is sent while authorized, no tool is executed, and no external provider is used.

Evidence is written to `.artifacts/hipi-work/packages/gui-smoke/`:

- `packaged-gui-smoke.json`: outcome, OS/architecture, host Node and Electron versions, source/provenance/harness/binary/ASAR hashes, checks, errors, cleanup state, and artifact hashes.
- `initial.png`, `streaming.png`, `completed.png`, `reopened.png`: actual renderer captures at the observed stages. A fast stream can finish before the streaming screenshot is captured; incremental updates are established by DOM observation, not the screenshot filename.
- `activities.png`, `activities-reopened.png`: successfully loaded activity dialogs on the first launch and restart.
- `dark-completed.png`, `dark-reopened.png`: actual dark-theme conversation captures; the original theme preference is restored before the ordinary completion/reopen captures.
- `tool-packs-active.png`, `tool-packs-uninstalled.png`, `tool-packs-reopened.png`: observed management states, not evidence of tool execution.
- Redacted native launch logs; failures include available process output.
- When the renderer remains connected, `failure.png` and `failure-controls.json` are captured before CDP disposal. The latter contains at most 100 control role/visibility/disabled/focused/hit-test records and allowlisted static action labels; unknown labels are redacted. It contains no HTML or input values. Failed capture is recorded without replacing the original smoke error. Click failures identify the requested text and last matching-control count/center hit result; focus-restoration timeouts identify the target through the same static-label allowlist, never dynamic conversation titles. Neither forces interaction through an overlay.

Screenshots require visual inspection. Automation does not certify typography, layout quality, physical Chinese IME input, accessibility, installation, OS trust/signing/notarization, production credentials/keychain, paid models, updates, sleep/resume, or power-loss recovery. The JSON explicitly records these limits. A screenshot's existence is not visual acceptance.

## Failure and cleanup

Windows early-start diagnosis uses a fixed project PowerShell script, without an execution-policy override. It binds the spawned main PID to its executable path, start time and current session before inspecting only that process's thread windows. At failure, identity is checked again before cleanup. Standard error dialogs are classified into fixed constants; raw titles, text, paths and stack traces are never exported. The observer does not click, close, focus, screenshot, or enumerate other processes' desktop contents. It is limited to eight windows, sixteen controls, 2048 characters per text control, a two-second enumeration budget and a ten-second outer helper timeout. Query denial, changed identity or invalid helper output produces `unknown`, with no alternate collection route.

Cross-process dialog text uses bounded [WM_GETTEXT through SendMessageTimeout](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw), since [GetWindowText cannot retrieve another application's control text](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowtextw). This can expose a generic Hipi startup modal or Electron module-load error before DevTools exists. Missing dialogs do not establish the startup cause. `gui-windows-dialogs.test.mjs` exercises privacy/identity failures on all platforms and a self-expiring owned native dialog on Windows; other platforms explicitly skip that native test. The test fixture closes only its own dialog, not application windows. Native observation remains unverified until the Windows test actually runs.

CDP requests, discovery bodies, process output, and waits are bounded. Early discovery rejection cancels the response body. Timeout cleanup waits for actual process close. An already exited process never authorizes signaling its old PID or process group. Remaining package processes cause a failed result and retained temporary directories rather than broader process killing. Temporary roots are removed only after owned process termination and absence of packaged helpers are confirmed.

Windows cleanup may observe matching package processes through CIM for up to ten seconds, including individual query deadlines. Only an actual empty result permits cleanup; a query error fails immediately, and processes still present at the deadline retain their directories. This is exit observation, not a workaround for an application launch failure. Failure evidence also reports fixed profile-directory/file metadata, including both owned session and profile `DevToolsActivePort` candidates. Alternate candidate contents are never read and no alternate port is contacted; symlink ancestors are not traversed. No user directory outside the owned fixture is searched.

The deterministic smoke alone passes `--enable-logging=file` and an explicit file inside its separate owned `native-diagnostics` directory. [Electron documents file logging as the reliable Windows child-process logging route](https://www.electronjs.org/docs/latest/api/command-line-switches#--enable-loggingfile). No application bootstrap or permanent logging setting is changed. Exported `chromium-0.log` and `chromium-1.log` are bounded to 1 MiB each, with owned paths, private debugging endpoints and sensitive-looking lines redacted. Readiness/flow observations fail on detected overflow, and final collection also refuses a successful result for overflow or read errors. Polling is not an OS disk quota: native writes can exceed the limit between observations. Missing logs remain explicit and do not establish a startup cause. Fixed profile metadata includes canonical-equality booleans from the harness Node process; these do not prove Electron used identical normalization.

Focused source tests are `test/smoke-profile.test.ts`, `scripts/cdp.test.mjs`, `scripts/gui-process.test.mjs`, `scripts/gui-profile-evidence.test.mjs`, `scripts/gui-native-log.test.mjs`, and `scripts/gui-flow.test.mjs` under `apps/hipi-work-desktop`. They cover main-entry wiring, profile validation, endpoint restrictions, request/transport lifetime, response cancellation, exit-before-close cleanup, bounded CIM observation, fixed metadata probes, bounded redacted native logs, modal geometry and scrolling, delayed workspace rendering, and explicit activity read success. They cannot substitute for running the packaged GUI on each required target platform. Exit-before-close is tested with controlled events on both OS branches; actual child-process tests do not assume POSIX pipe inheritance timing on Windows.
