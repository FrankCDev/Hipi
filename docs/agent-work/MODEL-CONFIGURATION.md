# 真实模型配置与执行边界

2026-10-19。状态：官方 OpenAI 纵向已接入协议 3、HTTP 与桌面，定向 mock 测试及桌面生产构建通过；没有使用真实密钥调用服务，系统密钥链、真实 GUI 与三平台仍待验收。以下记录实现约束与剩余验证，不等同于 RC 完成。

## 当前落地

- 模型目录与固定会话模型来自运行时，创建时显式选择；UI 不保存第二套模型事实。
- HTTP 开发宿主密钥仅保存在运行时内存；桌面通过独立 safeStorage 能力加密保存，拒绝不安全后端与明文降级。
- 真实 provider 禁 ambient auth 和自动重试；外部异常在进入 Durable 前转换为受控类别。
- 历史只读打开不恢复执行，恢复整个工作区须显式操作。
- 运行中取消映射 PI abort。暂停时只持久保存取消意图、撤回尚未派发的本地交付并设置原生 abort 标记，不启动 scheduler；尚需 PI 清理的状态显示 `cancellation_pending`，不能声称执行已经回滚。重启修复取消标记，显式恢复后才处理取消清理及其他任务。
- 新增暂停取消测试覆盖多会话隔离、意图落盘后故障、重启、未派发内容不重放及不读取 secret；真实外部请求的最终结果仍可能未知。

## 首个纵向目标

配置一个明确支持的 API Key 模型服务，创建会话时选择模型，提交任务后在现有工作台接收真实流式结果。模型配置、凭据可用与请求成功是三个不同状态；本地存在凭据不能显示为“服务验证通过”。首次实现优先使用一个官方 provider，其他协议与自定义服务地址再通过同一边界扩展。

## 使用现有公共能力

PI AI 的 `createModels` 接受 `credentials` 与 `authContext`，官方 provider 通过 `models.setProvider` 注册。现有 `openRuntime` 已接受 Models，无需在 UI 或 Electron main 中另写 Agent 循环。

会话的 `{provider, modelId}` 应交给 PI Durable 的 `agent.model` 持久化。创建后从 PI 读取同一事实，不同时在根目录索引维护可独立修改的模型选择。既有会话不能因全局默认值改变而静默换模型。模型 ID 可能包含斜线、点号等，不能套用工作区 ID 的校验正则。

必须显式禁用 ambient auth：注入不读取环境变量、文件凭据的 AuthContext。不得因用户启动应用的环境恰好存在 API Key 而自动产生付费请求。

## 凭据所有权

- 普通 AppClient 查询只返回服务商标识及 configured / locked / unavailable 等受控状态，不返回 API Key。
- 凭据设置通过独立、受限的平台能力接入。输入只在设置界面的临时内存存在，不能进入草稿、Query 缓存、localStorage、URL、日志或诊断包。
- Electron main 管理系统加密能力与加密凭据文件，runtime 仅通过私有的、带进程代次的通道获得执行所需凭据。不经命令行或环境变量传递。
- 使用 safeStorage 前检查实际可用性。Linux 明确拒绝 `basic_text`、未知后端或不可用状态的持久保存，不启用明文降级。系统存储不可用时须明确说明，而非伪装加密成功。
- 文件格式有版本与大小限制，串行更新、原子替换；解密或写入失败保留原文件。凭据文件位于工作区数据树之外，但这不是备份或诊断自动排除的保证，导出流程仍需明确排除它。
- 撤销凭据影响后续请求，不代表正在进行的外部请求已停止或费用被撤回。

这是产品实现设计，不是授权开发过程中填写、保存或使用用户真实凭据。实际连接与付费测试另行取得明确授权。

## 持续验证的执行风险

1. PI 会持久化 provider 错误消息及失败状态。仅在 UI 脱敏不足，须在错误进入 Durable 前清除密钥、原始响应正文及服务诊断中的敏感信息，同时保留受控错误类别与重试语义。
2. 当前测试宿主的 `resume: true` 会在打开工作区时恢复执行。真实模型必须区分读取历史与允许继续付费执行；凭据准备、恢复政策与用户操作先后关系必须有明确约束。
3. 现有 cancelWait 只停止观察与等待。执行取消要有单独命令及真实上游 abort 映射，不能把关闭订阅命名为停止生成。
4. utility 退出可能发生在服务已经接受并计费之后。恢复不得宣称模型请求 exactly-once；原提交回执与外部请求结果未知需要分别表达。
5. 当前源代码条件与 provider 子路径 exports 必须在实际打包中验证，不能通过私有深层导入绕过公开接口。

## 定向验证

使用确定性 provider 与虚构 secret sentinel 验证：模型引用重启后不变；缺失或锁定凭据拒绝派发；环境变量不会暗中启用服务；密钥不出现在数据库、消息、回执、普通配置和日志；加密不可用、损坏文件与原子替换失败保留数据；更新与提交并发、旧进程代次以及删除凭据后的新请求有一致语义。

真实服务测试和三平台系统安全存储测试单独记录。纯函数测试与 mocked provider 不能证明真实模型可用、凭据安全存储或费用准确。
