# 第二阶段：可信连接与日常工作台

2026-10-19。状态：可信连接与工作台基础的历史阶段边界，本文不是验收通过记录。用户现已授权持续推进 1.0 RC；当前执行范围见[首版范围](RELEASE-SCOPE.md)与 [RC 跟踪](RC-TRACKER.md)。以下“本轮”指第二阶段，不再限制后续实施或要求重新等待普通产品确认。

## 本轮要解决的问题

第一阶段具备受控的持久执行链路，但用户体验存在明确缺口：连接按钮未验证服务、创建失败只显示通用错误、前端端口与允许的 Origin 不一致难以诊断、刷新后导航与草稿丢失，以及界面信息层级和视觉质量不足。

本轮交付以用户可见的完整操作为单位：连接正确服务 → 发现或创建工作区与会话 → 输入与观察任务 → 切换、刷新及重连 → 找回原来的输入和结果。

## 实施边界

- UI 继续通过注入的 AppClient 使用应用契约，不依赖 Electron、Node 或存储实现。
- 增加只读握手和持久目录查询；HTTP 与 IPC 语义一致。只有鉴权与协议验证成功后才能进入已连接工作台。
- 服务地址不是存储身份。以持久的 storeId 隔离浏览器草稿与未决请求；重新连接时先确认服务身份，再恢复本地状态。
- 本地草稿不是执行事实；未决请求保留原 ID 和原 payload，重新查询回执，不能通过生成新 ID 自动重做。
- 后端持久目录发现保留已有工作数据；创建、登记、崩溃恢复和重复打开须有明确原子边界及测试。
- 凭据不写入浏览器普通持久存储。诊断只输出可安全显示的错误类别，不记录 token、请求正文、用户文件内容或完整内部异常。
- 不通过放开任意 Origin 来修连接问题。浏览器无法区分的 CORS 与网络失败应明确说明不确定性，而非伪造具体原因。

storeId 是本机数据存储的身份，不是用户身份或远程服务器证书。备份复制与恢复的身份语义、多窗口写同一草稿、浏览器存储失败与陈旧请求处理均须在实现文档与评审中明确，不能只加一个键前缀就宣称安全。

本轮浏览器端采取保守的单存储、单编辑窗口边界：使用 Web Locks 为当前 store 的本地草稿与未决请求持有编辑所有权；第二窗口明确提示占用并提供重试，不以读写 localStorage 的时间差充当原子事务。主动断开、卸载或浏览器结束须释放所有权；不支持所需锁能力时拒绝进入可写模式。此限制不删除核心多观察者能力，也不代表总体多窗口设计已完成。后续开放多编辑窗口前，应实现按会话分区的持久请求记录、草稿版本冲突与相应多窗口行为测试。

## 工作台设计方向

- 左侧紧凑、清楚的工作区与会话导航；中央以阅读和任务输入为主。
- 回执、内部 ID 和调试信息按需打开，不持续占用主工作区。
- 统一排版、间距、图标、分隔和语义颜色；明暗主题共用组件与状态规则。
- 空状态提供当前可执行的动作，不塞入与当前步骤无关的技术说明。
- 输入、流式阅读、历史滚动、会话切换和错误恢复保持连续；不能为自动滚动打断用户阅读。
- 加载、空、错误、禁用、焦点、长文本和窄屏是正式组件状态；中英文与中文组合输入一起处理。
- 未接入的文件编辑、Diff、模型配置等能力不放可点击假入口。

## 验收要求

1. 正确地址与凭据完成握手；错误凭据、端口、Origin、协议和不可达服务不会假装连接成功。
2. 工作区及会话目录在进程重启后仍可发现，列表查询不会隐式启动任务。
3. 创建中断、重复 owner 和索引恢复不会覆盖或删除已有会话数据。
4. 切换服务后草稿与未决请求不串入另一存储；刷新、重新选择会话后保留正确草稿。
5. 响应丢失后按原请求核对与重试；旧回执不清除用户后来写的新草稿。
6. 浏览器存储不可用或配额满时有明确反馈，不静默声称已保存；凭据不进入存储或诊断。
7. 真实界面验证布局、主题、语言、键盘、焦点、输入与恢复流程。静态检查和纯函数测试不能代替这一项。
8. 最终报告附实际检查输出，分清通过、失败、环境阻断和未运行；不以本阶段命名暗示生产 RC。
