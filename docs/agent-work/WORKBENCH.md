# 消息与文件工作台设计

日期：2026-10-19。用户已明确产品需求，技术库为待验证候选；本文不代表实现完成。遵循[架构决策](ARCHITECTURE.md)的 UI、契约与平台边界。

## 1. 已确定的体验

- 消息支持流式 Markdown 绘制，覆盖逐步到达、尚未闭合的代码块、列表和其他结构；避免每个 token 造成整段跳动或破坏选择与滚动位置。
- 右侧提供类 IDE 工作台：项目文件列表、文件查看、代码编辑以及最新修改的 Diff。
- 支持展示 Word、Excel、PDF、图片和 CSV。代码编辑是明确需求；Office 文件当前要求展示，尚未要求完整 Office 编辑能力。具体格式后缀、大小与保真范围在验证后明确。
- 文件、消息和预览使用一致的主题、字体、国际化、快捷键、焦点与错误反馈。后台加载或流式输出不能抢走编辑焦点。

例如 Agent 修改正在编辑的文件时，工作台应提示磁盘版本已变化，让用户比较差异和决定如何合并；不能用刷新覆盖未保存的输入。

## 2. 资源与扩展边界

UI 使用工作区 ID、资源 ID、受控 resource URI、文件元数据和内容版本，不能将本机绝对路径当作远程资源地址。资源读取、目录枚举、保存与权限判断通过 AppClient；桌面选择器等可选能力独立注入，能力不可用时明确降级。

建议以轻量文件处理 registry（注册表）调度查看器与编辑器：基于可信服务侧的文件类型探测、MIME 与必要的文件特征匹配，插件声明支持格式、只读/编辑能力和资源限制。扩展名不能单独作为安全判定。注册表先服务内置处理器，不因此提前承诺第三方 UI 插件安装机制。

处理器统一接收授权资源句柄、主题、语言、取消信号与生命周期接口，按需加载和释放 worker、对象 URL、订阅及缓存。大文件处理尽量在 worker 或独立进程完成；页数、行数、字节数、解压体积、内存和处理超时均有限额。具体限额经基准测试确定，超过限制给出部分展示、分页或明确拒绝原因。

## 3. 编辑与差异的正确性

- 编辑缓冲区与磁盘版本分开记录；dirty 表示有未保存修改，不能将其当成持久执行状态。
- 读取返回 revision；保存携带预期 revision，由可信服务侧检查版本并受控原子写入。版本不一致返回冲突，不静默覆盖 Agent、其他窗口或外部编辑器的更改。无条件覆盖需要单独的用户决策与权限检查。
- “最新修改”必须标明比较基线：一次任务执行前后、Git HEAD 与工作区、或编辑缓冲区与磁盘。三者不能混用；最近一次变化并不等于 Agent 的全部变更。
- 任务前后 Diff 需要对应版本或快照证据，不可从当前 Git diff 倒推出任务归属。文件新增、删除、重命名、二进制与无法建立基线的情况需明确显示。
- 恢复、撤销和应用补丁必须检查目标版本与作用范围，不能回滚用户的无关改动。尚未确定恢复功能的首版范围，不能因提供 Diff 就声称已支持安全恢复。

## 4. 解析与渲染安全

Markdown、文档中的 HTML、SVG、链接和嵌入内容均视为不可信输入。禁用任意脚本、危险 URL 与未经授权的外部资源请求；对需要的 HTML 做严格净化并隔离渲染。外链打开走受控能力，预览内容不能获得 preload bridge 或 Node 权限。拒绝危险内容与格式错误时保留原文件，不把解析失败解释为文件可安全执行。

默认在本地或已授权服务端处理文件，不自动上传外部预览服务。解析 Excel 不执行宏或不可信公式，显示文件已有结果时注明其可能不是重新计算后的值。CSV、压缩型 Office 文档和大型图片需防资源耗尽；不支持的格式明确提示，不伪造成功预览。

## 5. 待验证的库候选

- **Streamdown**：评估用于流式 Markdown，重点验证未闭合结构、代码高亮、链接安全、主题、中文与增量更新性能。
- **CodeMirror 6 与 @codemirror/merge**：评估代码编辑与差异查看；验证大文件、输入法、无障碍、版本冲突和三类 Diff 基线。用户提及 CodeMirror，不意味着已经确认其他产品使用它。
- **PDF.js**：评估 PDF 分页展示、缩放、搜索及 worker 生命周期；禁用不必要的嵌入执行和外部请求能力。
- **docx-preview**：仅作为 DOCX 预览候选，HTML 布局不保证与 Word 精准一致，也不覆盖旧版 DOC。其他 Word 格式及高保真要求另行评估。
- **SheetJS 加虚拟网格**：评估 Excel 数据解析与只读展示。文件解析不等于保真还原图表、分页、条件格式或公式计算，具体格式支持与许可证须核对。
- **PapaParse**：评估 CSV 分块/流式解析，配合虚拟网格；编码、分隔符、引号、多行单元格和错误行需有测试，导出时另行处理公式注入风险。

这些候选未安装、未进行兼容性或性能测试，也不代表相关格式已经可用。实施前核对官方文档、确切版本、许可证、依赖与维护状况；不为了预览同时引入重叠的大型套件。

官方资料：[Streamdown](https://streamdown.ai/)、[CodeMirror merge 当前仓库](https://code.haverbeke.berlin/codemirror/merge)、[PDF.js](https://mozilla.github.io/pdf.js/)、[docx-preview](https://github.com/VolodymyrBaydalka/docxjs)、[SheetJS](https://docs.sheetjs.com/docs/)、[PapaParse](https://www.papaparse.com/docs)。CodeMirror merge 的 GitHub 镜像已归档并指向新的仓库地址，不应将镜像归档推断为停止维护。

## 6. 验收与后续参考材料

测试覆盖：逐 token Markdown 与畸形内容、大文件和连续切换、解析取消、非法格式、受限文件授权、外链与脚本阻断、任务写盘与用户编辑冲突、保存版本校验及不同 Diff 基线。两种 AppClient adapter 下维持相同的资源授权和编辑语义，远程模式不假装有本机路径访问权。
