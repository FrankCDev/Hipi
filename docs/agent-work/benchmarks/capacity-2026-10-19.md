# Capacity benchmark: 2026-10-19

## Scope and evidence

Small serial directory workload through the public WorkRuntime API and real PI/SQLite. One temporary workspace per scale; 10, 100 and 1,000 empty archived conversations. Every seed is created then archived, so at most one conversation is active. No SQL fixture injection, provider requests, credentials, user files, purging, or VACUUM. Only the explicit deterministic test provider is assembled.

Primary run: [overlay JSON](capacity-overlay-2026-10-19.json). Exploratory run: [tmpfs JSON](capacity-2026-10-19.json). Script: [benchmark-capacity.ts](../../../packages/work-runtime/scripts/benchmark-capacity.ts). These runs do not qualify larger workloads or release readiness.

## Environment and reproducibility

- linux 6.18.55 x64; Node v24.19.0; SQLite 3.53.3
- AMD EPYC 9V74 80-Core Processor; 9 logical CPUs; RAM 9967.27 MiB
- Primary fixtures were on the workspace overlay filesystem (32 GiB filesystem; approximately 27 GiB free at launch), not a qualified physical SSD. Exploratory fixtures were on /tmp tmpfs. Neither run validates storage power-loss behavior.
- Shared environment: other workers were running checks. CPU isolation, OS cache flushing and forced garbage collection were not used.
- No .git directory was available, so gitHead is null. Each JSON includes before/after SHA-256 hashes for the script, lockfile and runtime/durable/ai source files. This hashes the listed source scope, not the complete installed dependency tree.
- Primary before/after changed sources: ["packages/work-runtime/src/extensions/pack-schema.ts", "packages/work-runtime/src/extensions/pack.ts"]. Directory/core/PI hashes stayed unchanged, but the worktree was not globally frozen; preserve this qualification when quoting results.

Rerun from repository root:

```sh
TEMP_PARENT=$(mktemp -d /path/to/persistent-volume/hipi-capacity-XXXXXX)
TMPDIR="$TEMP_PARENT" node --conditions=source packages/work-runtime/scripts/benchmark-capacity.ts --output=/absolute/new-result.json
rmdir "$TEMP_PARENT"
```

The default is serial: scales 10,100,1000; 30 samples per operation; three fresh-process cold reads; 30 seconds idle per scale. Parameters: --scales, --samples, --restarts, --idle-ms, --min-free-bytes (default 1 GiB), --max-rss-bytes (default 2 GiB). Use a new output path; existing files are never overwritten. Higher-scale runs require explicitly chosen parameters and suitable storage/RAM. Guards check RSS and free filesystem space at bounded workload intervals; they are not OS-enforced reservations. Each child has a one-hour safety timeout.

## Method

- Initialization/schema/Harness creation, fixture construction and initial projection catch-up are measured separately from steady state. No legacy migration was benchmarked; new-store schema cost must not be called migration performance.
- Seeded directory pages are traversed and checked for exact count and unique IDs; default active list is checked empty. Tail timing uses the valid cursor obtained from that traversal. At 10 records the tail is also the first page.
- Steady first/tail pages each have 30 sequential samples at exactly the stated seed scale, with no concurrent mutation.
- After closing the runtime, three independent Node processes open and read the directory. Imports and process startup are excluded; the OS page cache remains warm. These are cold runtime reads, not cold disk measurements.
- The first mutation after reopen is excluded from steady state. Then 30 cycles perform create, rename, archive, restore and rearchive. The final historical totals are therefore 41, 131 and 1,031, respectively. Each mutation has a fresh request ID; replay performance is not measured.
- Metadata timings include authoritative PI commits but exclude deferred root projection. Projection catch-up is reported separately: 2N expected seed changes initially and 152 expected changes after workload. These are workload-derived counts, not a private SQL backlog query.
- Quantiles use nearest rank. p95 from 30 observations is descriptive, not a stable service-level guarantee. The JSON preserves all raw steady samples and cold observations.

## Interpretation and remaining work

The measured small-scale directory operations completed without exceeding the live-conversation quota. This establishes a repeatable measurement path, not long-term capacity or production stability. Compare cold catch-up separately from steady reads; the read path still opens SQLite and validates projection metadata, so first/tail-page timing must not be treated as a pure indexed SQL query.

At 1,000 seeded conversations, steady first/tail p95 was 9.88/10.15 ms; the first 2,000-change projection catch-up was 267.86 ms. The 100-to-1,000 idle RSS rose from 127.84 to 202.07 MiB. These observations warrant follow-up on read-path and cache costs; they do not establish complexity, a leak, or behavior at 10,000 records.

The exploratory tmpfs run changed core.ts, node.ts and store-catalog.ts during execution and retained an extra closed runtime reference in the original script. Its hashes and raw values remain diagnostic only. Do not mix its memory or latency values with the primary run as an isolated filesystem comparison.

Not measured: 10k+ conversations, 100k audits/receipts, grants/revocations/approvals, retained context, model submissions, large message/proposal payloads, legacy migration, index corruption/rebuild faults, power loss, long-duration memory, multi-workspace eviction, concurrency, HTTP/IPC/UI, Windows or macOS. Candidate budgets in the [capacity design](../CAPACITY-AND-ARCHIVAL.md) remain unqualified.
