# 桌面宿主纵向实现

2026-10-19。状态：开发中，尚无桌面端验收通过结论。

## 目标与边界

在已经交付的持久会话、目录、可信连接与工作台基础上，增加真实 Electron 宿主。用户启动桌面应用后直接连接本机 runtime，不需要复制 HTTP 地址或 token。浏览器 HTTP 入口继续使用相同 AppClient 与工作台。

本次纵向范围为：启动窗口 → 握手确认存储身份 → 创建工作区与会话 → 提交输入并观察结果 → 重载视图 → 退出与重新打开。先使用明确标识的确定性测试模型；它不能替代真实模型、工具执行或生产可用性验收。

## 职责与所有权

- Renderer 只使用浏览器安全的应用契约与注入的 AppClient。桌面组装入口负责选择适配器，功能组件不依赖 Electron。
- 沙箱 preload 只暴露受限、可序列化的调用与观察能力。不暴露原始 IPC、任意通道、进程对象或任意路径读写。
- Main 管理窗口、可信来源校验和 runtime 生命周期，不打开业务数据库。来自 iframe、未知窗口或非预期页面的调用必须拒绝。
- Utility process 持有现有 Node runtime 与 SQLite owner，通过 Electron 的 parentPort 通信。已有 Node child_process IPC 适配器不能直接充当这一实现。
- Utility process 是故障隔离边界，不是执行第三方工具的权限沙箱。

## 故障与恢复不变量

1. 进程创建成功不等于服务就绪。完成持久化初始化和握手后才允许工作台执行操作。
2. 每个运行实例有独立代次；退出实例的迟到响应与事件不能更新新连接。请求、订阅、待确认事件和等待时间必须有界。
3. 首次确认的 storeId 持续校验。服务替换不能静默绑定另一份数据，也不能把旧草稿提交到新存储。
4. runtime 退出时停止接受新写入，关闭观察并报告未决操作结果未知。恢复时按原 requestId 查询回执，不自动生成新请求重做操作。
5. 页面重载只重建观察与视图，不因此启动第二个 runtime。退出应用先停止接收请求并等待已接受工作清理；超时处理不能宣称所有工作已经成功完成。
6. Electron 单实例策略与 SQLite 单写入锁各自保留；前者不能替代后者。取消等待不能表示取消执行或回滚。

## 验证与发布门槛

- 针对性测试覆盖来源拒绝、协议错误、重复与迟到响应、观察清理、慢消费者、进程退出及原回执核对。
- 实际 Electron utilityProcess 验证与普通 Node 通道测试分开记录；模拟 peer 的测试不能宣称 Electron 链路已通过。
- 图形验证覆盖启动、工作区创建、会话切换、输入法、主题、语言、键盘和重载。没有实际显示环境时保留阻断项。
- 构建需遵守根 AGENTS.md 的授权要求；打包资源还需验证非仓库工作目录、空格与非 ASCII 路径。
- Windows、macOS、Linux 的安装、退出、更新、原生存储和适用签名分别提供证据。单一 Linux 源码测试不能代表跨平台交付。

真实模型配置、流式 Markdown、文件编辑与 Diff、文档预览和插件闭环继续按[首版范围](RELEASE-SCOPE.md)推进，不因新增桌面窗口而视为完成。

## 依赖审查记录
