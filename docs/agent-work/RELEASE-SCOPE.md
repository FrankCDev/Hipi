# 1.0 RC 首版执行范围

日期：2026-10-19。状态：用户已授权持续完成全部首版对接并推进 1.0 RC，普通产品与工程决定由负责人直接作出。本文是当前执行范围，不是实现结果或发布日期；不再停留在仅文档评审阶段。实现矩阵、依赖顺序及发布阻断以 [RC 跟踪](RC-TRACKER.md)为准，验收必须有实际证据。

依据：[愿景](../../VISION.md)、[架构决策](ARCHITECTURE.md)、[工作台设计](WORKBENCH.md)。页面见[页面清单](SCREENS.md)，交付判断见[验收清单](ACCEPTANCE.md)。

## 1. 一句话定义首版

让本地单用户在多个工作区中管理多个任务，完整走通“目标 → 上下文 → 授权 → 执行 → 文件成果 → 查看、编辑与验收”，中断后能理解真实状态并安全继续。

范围必须同时兑现跨平台、好看、交互友好、插件生态、可靠、稳定六个标签。多任务包含列表、切换、排队和受限并行；不等于无限并发。并发、队列、文件、事件缓冲与存储限额须测量后设定，不能无限增长。

## 2. 首版必须形成的闭环

| 能力 | 首版执行边界 | 完成时用户能观察到什么 |
| --- | --- | --- |
| 首次使用与工作区 | 本地单用户；建立、打开、切换工作区；配置获支持的模型连接并检查可用性 | 知道数据在哪里、权限范围是什么；配置失败可修正，不丢输入 |
| 会话与任务管理 | 创建、按标题筛选、重开、分页历史与空闲会话归档/恢复；身份与执行关系遵循领域设计。永久删除、历史全文搜索和用户分支界面后置 | 能找到先前工作、理解继续会话与新执行的区别；归档不删除成果、历史或授权审计，不隐式停止任务 |
| 目标与上下文 | 新建任务、编辑提交前草稿、选择已授权上下文、说明预期成果 | 提交前可检查目标、工作区、上下文和权限；提交后可查询接收回执 |
| 执行与协作 | 持久任务记录、受限多任务、流式 Markdown、工具活动、补充信息、授权批准/拒绝、执行取消 | 当前在做什么、为何等待、何时需要用户操作都有可信依据；不编造进度 |
| 中断与恢复 | UI 重载、runtime 崩溃、连接丢失、应用重启后的状态重建；不确定副作用有核对流程 | 草稿和未保存编辑按明确策略保护；任务恢复不重做无法确认安全的操作 |
| 成果与文件 | 右侧项目文件树、成果入口、代码/文本编辑保存、版本冲突处理、基线明确的 Diff | 能定位成果与验证证据，区分部分成果、待验收与已验收；Agent 输出结束不自动等于验收成功 |
| 多格式展示 | Word、Excel、PDF、图片、CSV 的只读展示能力；具体后缀、保真和大小范围待验证 | 支持的文件能查看；超限、损坏、不支持或部分还原时明确说明。Office 不提供完整编辑承诺 |
| 主题与国际化 | 全局与约定区域的字体、配色、背景；预设、预览、导入导出与重置；文案及格式本地化 | 覆盖消息、文件树、编辑器、预览容器、弹窗与异常状态；缺失字体和非法配置可安全回退 |
| 插件生态最小闭环 | 版本化 SDK/契约、开发说明、可运行官方扩展示例、受控安装、启停、配置、卸载、权限与兼容检查、故障隔离 | 用户能安装示例、授权其声明的能力、在真实任务中使用、撤销权限并排查失败；不是空入口 |
| 诊断与桌面交付 | 脱敏诊断、问题定位、Windows/macOS/Linux 的安装和更新路径及失败恢复 | 用户能获知故障影响、保留工作并选择恢复动作；适用签名与发布渠道先决条件有证据 |

模型第一纵向采用官方 OpenAI 公开接口/API key 方向，具体最小协议由实现负责人记录；显式禁用 ambient auth，不预设所有上游模型或任意兼容服务均进入首版。凭据所有权、错误脱敏和 inspect/resume 边界见[模型配置](MODEL-CONFIGURATION.md)。测试优先使用确定性 provider；实际凭据和真实付费测试仍须具体授权并记录成本。

插件首先由负责人选择一个明确的受控扩展面完成上述闭环；MCP、Skills、运行时扩展与 UI 插件分别定义职责和权限，不宣称一套 SDK 已覆盖全部机制。具体首发契约与信任策略在实现前记录，不再等待普通产品决策确认；第三方任意 UI 代码加载不作为默认承诺。

## 3. 不可削弱的边界

- Electron + TypeScript main 是薄宿主；Agent runtime 独立进程运行，PI Durable 由薄适配层接入并固定经验证版本。SQLite 的打包、单写入、迁移和恢复路径必须实测。
- UI 经 `AppClientProvider` 注入 AppClient，只依赖应用契约；IPC/HTTP client adapters 位于组装边界。核心不依赖 Electron 或 HTTP 框架，权限在可信服务侧执行。
- 同一 UI 与契约须通过 IPC 和受控本地 HTTP 两种方式验证。HTTP 仅验证接入等价性，不承诺公网服务；loopback 仍须认证、来源检查与安全绑定。
- shadcn/ui、Tailwind CSS、TanStack 家族为方向，已有具体依赖以工作区 manifest 和锁文件为准；代码编辑采用 CodeMirror 方向，兼容、安全和性能须实际验证，不能从选型推导完成。
- “请求已发送”“已接受”“已执行”“结果已确认”分开表达。断线与超时不能自动推导失败；结果未知时先核对，不盲目重试。
- 取消等待不等于取消执行，取消执行不等于回滚。关窗、退出宿主、runtime 存活和停止任务的具体策略需评审；首版不默认承诺独立常驻后台服务。
- 仅展示真实可用的能力；不可用功能隐藏或解释禁用原因，不放可点击却无实际结果的假按钮。原型模拟数据必须明确标注。

## 4. 明确后置

- 公网托管、多租户、团队协作、跨设备同步、服务器部署与运维产品。
- 插件市场、搜索排名、商业化、任意第三方 UI 扩展的普遍兼容。
- 完整 Office 编辑、保证与 Office 像素级一致的预览、任意格式与无限大文件。
- 自动撤销任意工具或外部副作用、通用安全回滚；Diff 不代表已有撤销能力。
- 未明确需求的复杂编排、无限并行和独立后台常驻服务。
- 会话永久删除、聊天历史全文搜索、跨工作区移动及面向用户的 fork/分支编辑界面。基础标题筛选与归档恢复在首版内；底层原生分支/子代理关系不得被破坏。

后置不改变核心任务、文件安全、权限、恢复与插件闭环要求。若验证证明某项首版能力不可交付，须提出影响和替代方案评审，不能悄悄删除。

## 5. 小而完整的里程碑

当前先推进真实模型核心纵向，同时执行真实桌面构建门禁；下一步设计并实现文件权限端口，再接文件工作台、预览与受控扩展。归档、主题和诊断按依赖并行。下列分组保留为交付检查点，不意味着重新等待用户批准已授权的普通设计和实施；详细依赖见 [RC 跟踪](RC-TRACKER.md)。

1. **核心领域架构与交互基线**：本组文档评审后，先补齐核心领域详细设计，再完成主工作台高保真原型。明确 workspace、用户可见 conversation、task/run 与 PI Durable `Session` / `Conversation` 的关系及所有权；必须核对上游事实，不能仅凭名称作一一映射。评审状态持久化、并发、单写入者、创建/重开/恢复/归档/删除生命周期、资源清理、权限与成果归属。原型再走通会话导航、正常任务、等待授权、结果未知、编辑冲突和重启恢复。退出条件是领域边界、状态转移及关键动作可解释，非生产实现完成；不能从分层通信图直接进入生产实现。
2. **三个技术验证**：获准实施后分别验证下列风险，交付可复现记录；失败先调整方案，不堆叠完整功能。
   - PI Durable + Electron 独立 runtime + SQLite：三平台原生模块与打包路径、单写入、崩溃前后持久事实及副作用核对；不能由进程崩溃恢复推导断电安全。
   - IPC/HTTP 等价：同一 UI 与应用核心执行提交、回执、流、断连、重连、取消与结果查询；验证授权、来源、重复请求、事件缺口与结果未知。
   - 流式消息 + 编辑器 + 多格式预览：真实长会话与文件语料下同时输入、滚动、切任务、编辑、加载/取消预览，测量性能、资源释放和冲突保护。
3. **可使用的纵向版本**：把一个真实任务从创建做到成果验收，再覆盖多工作区、多任务、主题、国际化与官方扩展完整生命周期。退出条件是相应验收项有实现和实际证据。
4. **发布候选加固**：补齐三平台安装更新、故障恢复、安全、长时间负载与可访问性证据，关闭发布阻断项。目标为 1.0 RC；具体发布日期和实际发布操作不从该目标自动推导。

## 6. 实施中需记录的工程决定，不能用默认值冒充验证

- 首发优先真实任务、官方 OpenAI 首个协议与联网边界、中英支持的完整范围及 RTL 边界。
- 支持的系统最低版本、CPU 架构、Linux 分发形式、最低硬件；所有性能和资源预算。
- 主题区域清单与背景资源来源；各文件格式后缀、展示保真与限额；草稿和未保存编辑的恢复策略。
- 插件首发扩展面、SDK 版本策略、安装来源/完整性与信任方式、隔离实际保证。
- 关窗、退出、系统休眠时的任务行为；更新执行时机、安装分发、签名/公证、迁移备份与恢复责任。
- 具体依赖与工具版本、发布版本/日期；是否及何时建设托管服务。

这些普通工程决策由负责人按里程碑直接解决并记录依据，不再逐项等待用户确认；涉及实际凭据、付费、安全权限或永久删除的操作仍遵守确认边界。权限、数据与恢复设计必须在对应实现前明确。数值预算先测量再确定，TBD 不是发布时免验收的理由。旧文档中的范围建议以本文及 RC 跟踪为当前基线；既有安全约束和未通过验收不会因此消失。
