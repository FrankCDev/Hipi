# 首版页面与状态清单

日期：2026-10-19。依据[首版范围建议](RELEASE-SCOPE.md)。这是信息架构与下一步设计输入，不代表已有页面、路由或交互实现。页面可以是同一工作台的区域、抽屉或对话框，不强制拆成独立路由。

## 1. 页面清单

| --- | --- | --- | --- |
| S01 首次使用 / 工作区 | 理解本地数据与权限，建立或打开工作区，配置模型连接 | 选择工作区、测试连接、修正配置、继续/返回 | 首次空态、无权限、路径失效、连接失败、未完成设置、离线；失败保留输入 |

## 2. 主工作台交互骨架

- 工作区与任务切换保留各自输入草稿、阅读位置和已打开资源；切换不取消执行，也不把另一个工作区缓存带入当前任务。
- 中间优先展示目标、当前状态、需要用户的动作和成果；完整工具日志按需展开。流式输出不强制抢回滚动位置，离开底部后提供新内容提示与回到底部入口。
- 右侧在文件树、编辑器、Diff 和预览之间切换，支持面板收起与尺寸调整。窄窗口仍能访问关键动作，不挤压成不可操作布局。
- 未保存编辑有稳定标识。Agent/外部修改触发版本冲突提示，用户可比较，不能静默覆盖。关闭文件、切换工作区与退出对未保存内容采用一致保护策略。
- 授权展示具体能力、资源/目标、作用范围与后果；批准与拒绝均有回执。等待授权期间仍能查看其他任务；不通过通知文案暗示已获授权。
- 执行状态、连接状态、请求回执与成果验收是不同维度。例如“连接中断，任务最后已知运行中，取消请求待确认”必须可以同时表达，不能压成“失败”。
- UI 只调用注入的 AppClient。桌面能力缺失时解释替代流程；HTTP 验证环境不把本地文件选择伪装为服务器路径访问。

## 3. 跨页面设计要求

每个关键动作都设计成功、等待、失败、重复操作和中断路径。全局/区域主题的继承与重置、长译文、中文输入法、字体回退、缩放、键盘焦点、屏幕阅读器语义与减少动态效果贯穿所有页面。预览内容本身可有格式限制，容器与操作仍须可读可用。

关窗不暗示任务停止，取消不承诺撤销已完成的外部操作。具体关窗/退出策略确定后，确认文案必须精确说明运行中任务和未保存编辑将发生什么。

## 4. 下一步高保真验证

先完成核心领域详细架构评审，明确用户会话/任务与 Durable 对象关系、持久化和生命周期，再完成 S02 主工作台及其 S03/S04 关联状态，最后覆盖 S01/S05/S06/S07；不先堆独立页面。用户可见会话不预设等于上游 `Session` 或 `Conversation`。用下列故事验证交互：

1. 新工作区 → 配置连接 → 提交目标与文件上下文 → 授权 → 流式执行 → 成果预览与代码编辑保存 → 验收。
2. 多任务同时存在 → 切换与补充输入 → 一项等待授权 → 拒绝后继续处理其他任务；看清资源排队原因。
3. 回包丢失/连接断开 → 展示最后确认状态 → 重连查询；外部操作结果未知时进入核对，不自动重做。
4. 用户编辑未保存 → Agent 修改同文件 → 比较冲突 → 保留用户内容并明确保存结果。
5. 取消请求、关窗与应用重启 → 分别展示真实影响 → 恢复任务与草稿；不把模拟流程当作恢复实现证明。
6. 主题和语言变化 → 长消息、预览错误、权限弹窗仍可操作；全程键盘操作且焦点不被流式输出抢走。
7. 查找并重开已有会话 → 辨认历史与新执行 → 按已评审策略归档/删除；清楚说明运行中任务、成果文件、历史记录与授权受何影响。

退出条件：评审者无需理解内部架构就能辨认当前状态、下一步动作和数据风险；记录未解决的交互问题。领域评审后可与[三个技术验证](RELEASE-SCOPE.md)并行，双方关键阻断问题解决后才进入获准的生产实施。
